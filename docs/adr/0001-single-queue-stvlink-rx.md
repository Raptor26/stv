# Приёмный тракт без маршрутизатора: диспетчер читает очередь парсера напрямую

**Статус:** accepted

> ADR хранится в репозитории stv, потому что решение меняет состав самой
> библиотеки: классы-маршрутизаторы удалены из stv для всех проектов,
> использующих stv и karavan.

Приёмный тракт stvlink исторически строился в три слоя: парсер кадров →
очередь парсера → маршрутизатор по `dst_id` → очередь модуля →
диспетчеризация по идентификатору сообщения в cambridge (паттерн рассчитан
на нескольких потребителей). Практика интегрирующих проектов показала, что
входящие сообщения всегда обрабатывает ровно один модуль: в хеш-таблице
маршрутов регистрировалась единственная очередь, а дополнительные
зарегистрированные очереди (например, `heartbeat_msg_queue`,
`dst_id = route_idx_t::heartbeat`) оказывались глухими — их никто не читал
и никто на этот `dst_id` не отправлял. Маршрутизатор в такой конфигурации —
чистый оверхед: лишний хоп (латентность до периода опроса маршрутизатора),
буферы RAM, отдельный контекст потока/таймера и слой кода.

Решено удалить понятие маршрутизатора из библиотек целиком:

- классы `stv::stvlink_route` и `stv::mavlink_v2_route` удалены из stv
  вместе с их тестами;
- модуль cambridge конструируется напрямую на выходной очереди парсера
  (типы совместимы — `etl::iqueue<sim_buff>`);
- проверка `dst_id` при приёме не выполняется: поле остаётся в заголовке
  на проводе и отправитель продолжает его заполнять (бинарная
  совместимость не нарушается), но приёмник его игнорирует — на линке
  точка-точка с единственным пэром адресная фильтрация не несёт нагрузки.

Значение `route_idx_t::heartbeat` в `karavan/route_definitions.hpp` **не
удаляется** и не помечается `[[deprecated]]`, а снабжается комментарием
«зарезервировано, не использовать»: `dst_id` передаётся на проводе как
`std::uint8_t`, и удаление первого значения enum сдвинуло бы нумерацию
(`cambridge_mcu` 1 → 0), нарушив бинарную совместимость с уже выпущенными
прошивками и GUI; атрибут `[[deprecated]]` в общей библиотеке karavan дал
бы предупреждения (при `-Werror` — отказ сборки) в других проектах.

## Considered Options

- **Оставить классы-маршрутизаторы в библиотеках «про запас»** — отвергнуто:
  мёртвый код требует сопровождения и тестов, а при появлении реального
  второго потребителя класс восстанавливается из истории git за одну
  операцию.
- **Фильтрация `dst_id` на приёме (в обёртке модуля или как параметр
  `karavan::cambridge`)** — отвергнута: на линке точка-точка с единственным
  пэром проверять адресат не от кого; поле игнорируется, но остаётся в
  формате кадра, поэтому бинарная совместимость сохраняется.
- **Удалить `route_idx_t::heartbeat` из enum** — отвергнуто из-за нарушения
  бинарной совместимости протокола (см. выше).

## Consequences

- **Ломка API stv:** `stv/communication/stvlink_route.hpp` и
  `stv/communication/mavlink_v2_route.hpp` удалены; проекты, использующие
  эти классы, при обновлении библиотеки обязаны перейти на прямое чтение
  очереди парсера модулем.
- Суммарный буфер приёма ужимается до ёмкости одной очереди — всплески
  сообщений длиннее её ёмкости между тиками обработки будут отбрасываться.
  Ёмкость очереди парсера — параметр интегрирующего проекта, этот ADR её
  не фиксирует.
- Кадр с валидным CRC и любым `dst_id` диспетчеризуется по идентификатору
  сообщения вместо отбрасывания — приемлемо для закрытого линка с одним
  пэром.
- **Условие отката:** появление второго пэра на линке или второго
  потребителя входящих сообщений (новый осмысленный `dst_id`) — тогда
  класс-маршрутизатор восстанавливается из истории git, возвращаются
  проверка `dst_id` и очереди модулей, а этот ADR помечается superseded.
- Схема `stv/include/stv/communication/stvlink.plantuml` описывает только
  одноочередную топологию: парсер → очередь → диспетчер → обработчик.
