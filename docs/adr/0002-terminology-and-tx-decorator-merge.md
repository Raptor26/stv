# Унификация терминологии обмена и объединение передающих декораторов stvlink

**Статус:** accepted

> ADR хранится в репозитории stv, потому что решение задаёт единую
> терминологию и имена API для всех проектов, использующих stv и karavan.

После удаления маршрутизаторов (ADR
[0001-single-queue-stvlink-rx.md](0001-single-queue-stvlink-rx.md)) имена в
коде перестали отражать роли сущностей: заголовок сообщения назывался
«маршрутизационным» (`stvlink_route_tx::routing_header_t`) при отсутствии
маршрутизации; диспетчер назывался «процессором»
(`cambridge_message_processor`); идентификатор сообщения имел разные имена
в разных протоколах (`pack_id`, `msg_id`, `type`). Разночтения провоцировали
ошибочные имена переменных и методов в интегрирующих проектах.

Решено зафиксировать единый глоссарий (раздел «Терминология» в
[stvlink.plantuml](../../include/stv/communication/stvlink.plantuml)) —
кадр, сообщение, заголовок сообщения, парсер, диспетчер, идентификатор
сообщения, адрес получателя, таблица обработчиков, обработчик, модуль — и
привести имена в коде к нему:

- `pack_id` → `msg_id` — единое имя идентификатора сообщения; в протоколе
  CRSF поле `type` сохранено как осознанное исключение (имя из
  спецификации протокола);
- `karavan::cambridge_pack_id` → `karavan::cambridge_msg_id`
  (файл `cambridge_pack_id.hpp` → `cambridge_msg_id.hpp`);
- `karavan::cambridge_message_processor` → `karavan::cambridge_dispatcher`,
  `cambridge_message_processor_fnc_type` →
  `cambridge_message_handler_fnc_type`, метод `handle_message` →
  `dispatch_message`;
- передающие декораторы `stv::stvlink_frame_tx` и `stv::stvlink_route_tx`
  объединены в один: `stv::stvlink_frame_tx` формирует кадр целиком
  (стартовая последовательность, `frame_size`, заголовок сообщения,
  CRC-16); заголовок сообщения — вложенная
  `stvlink_frame_tx::message_header_t{dst_id, msg_id, pload_size}`.

> **Примечание (2026-09-16).** Имена декораторов позднее уточнены, чтобы
> подчеркнуть роли «декоратор парсера» / «декоратор передатчика»:
> `stv::stvlink_receiver` → `stv::stvlink_parser` (файл
> `stvlink_parser.hpp`), `stv::stvlink_frame_tx` → `stv::stvlink_sender`,
> `stv::mavlink_v2_frame` → `stv::mavlink_v2_parser`,
> `stv::mavlink_v2_frame_tx` → `stv::mavlink_v2_sender`; в karavan аналогично
> переименованы кадровые декораторы протокола обмена с полезной нагрузкой
> по ролям «парсер» / «передатчик». Решения ADR не
> меняются: терминология и формат кадра на проводе прежние, меняются
> только имена типов. Текст ADR ниже сохранён в исторической редакции.

Раскладка байт на проводе не изменилась: golden-тесты формата кадра
проходят без модификации, бинарная совместимость с выпущенными
прошивками и GUI сохраняется.

## Considered Options

- **Оставить исторические имена, зафиксировав терминологию только в
  документации** — отвергнуто: документация не мешает новым разночтениям
  в коде; цель глоссария — быть источником имён.
- **Унифицировать поле `type` в CRSF до `msg_id`** — отвергнуто: имя
  перестало бы соответствовать спецификации внешнего протокола (TBS
  Crossfire), затруднив сверку кода с документацией протокола.
- **`message_id` вместо `msg_id`** — отвергнуто: `msg_id` уже использовался
  в протоколе karavan и короче при той же однозначности.

## Consequences

- **Ломка API stv и karavan:** переименованы публичные типы, поля и файл
  заголовков; проекты-потребители при обновлении библиотек выполняют
  механическую замену имён (поведение и формат на проводе не меняются).
- `stv::stvlink_frame_tx::header_size()` теперь возвращает 8 (канальный
  заголовок + заголовок сообщения); для срезания только заголовка
  сообщения на приёме используется
  `stv::stvlink_frame_tx::message_header_size()` (4).
- Имена `stvlink_route_tx`, `routing_header_t`, `pack_id`,
  `cambridge_message_processor` в кодовой базе больше не встречаются;
  слово «маршрутизатор» не используется ни в коде, ни в документации.
